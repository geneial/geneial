# Documentation workflow

- `README.md`: concise build, install, example, and integration entry point.
- `docs/Overview.md`: architecture and safety contracts.
- `docs/Demos.md`: runnable examples, flags, objectives, and provenance.
- `docs/Migration.md`: intentional API and behavior changes.
- `docs/Validation.md`: dated, observed validation results and unverified platforms.
- `docs/site/`: dependency-free gallery and HTML getting-started guide.
- `TODO.md`: explicit remaining work with acceptance criteria.
- Public headers: API reference generated by Doxygen’s optional `doc` target.

Build the site with `cmake --build --preset release --target website`. Serve
`output/release/site` with a local static server or open `index.html` directly.
Run `cmake --build --preset release --target doc` to generate API HTML under
`output/release/src/doc/html`. Pages automation copies it into `site/api`.

Use relative links within a generated site, semantic HTML, meaningful alt text,
keyboard-accessible controls, responsive layouts, and no third-party scripts or
fonts. Verify generated SVG as XML and inspect desktop/mobile rendering. Keep
the guide and Markdown workflows in sync; do not hand-edit generated artifacts.
Deployment/domain configuration is administrative work separate from a local
documentation build. Never embed credentials in deployment scripts.
