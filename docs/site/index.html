Evolutionary search in C++

A genetic algorithm library with interchangeable selection, crossover, mutation, and stopping criteria.

Define a fitness function, choose the operators, and inspect how the population changes. The examples below include their run history, output, and source.

Examples

Five recorded C++ searches and an interactive maze. Replays can be paused and scrubbed by generation.

01 Voronoi portrait

Variable-length geometry with residual-guided cell placement. Region colors are fitted to the target; evolution searches the positions and cell count.

Seed 42 · 24 initial cells, up to 256 · 6,000 generations

ReplayCSVSource

02 Triangle portrait / EvoLisa

Overlapping translucent triangles, multiscale geometry mutations, and local color refinement. A hybrid genetic search, not a pixel-perfect reconstruction.

Seed 42 · 96 triangles · 12,000 generations

ReplayCSVSource

03 Travelling salesperson

Minimize a closed tour through 48 points. Permutation crossover and swap mutation preserve a valid route through every point.

Seed 42 · 48 stops · 2,000-generation budget

ReplayCSVSource

04 N-queens

Place one queen in each row and column, then minimize diagonal conflicts. The search stops early if it finds a conflict-free board.

Seed 42 · 20 queens · 3,000-generation budget

ReplayCSVSource

05 Palette image

Each gene selects a pixel’s palette entry. N-point crossover and mutation reduce RGB squared error against a small procedural target.

Seed 42 · 768 genes · 5,000 generations

ReplayCSVSource

06 Random maze

Evolve direction sequences through a connected random maze. Change the seed, step the population, and inspect the corridor-distance fitness field.

About these runs

Portraits retain a 396 × 599 reference and score an 85 × 128 image to bound CPU work. Both use fitted colors in addition to genetic operators. Maze fitness uses a distance field, but does not inject a solved route. These are examples of search techniques, not claims of optimality.

Native seeded runs repeat within the same build and standard library. Results may differ across toolchains. Algorithm references and image provenance.

Build and run

Requires a C++20 compiler and standard library, CMake 3.21+, and Ninja. Boost.Test is used by the test suite, not the library.
